# Umbrella #191 — automatic hardware-aware mixed-format compiler (sprint design v1)

Status: DRAFT for ChatGPT advisory review. Branch: `feat/colic-auto-planner` (base: PR #189 tip + main).

## Deliverable

`colic compile MODEL --target auto --context N --objective O` → deterministic mixed-format
package; `colic plan` prints the same decision as JSON + text without emitting; saved plan
manifest replays for reproducible emission. First concrete targets: x86-64 AVX2
(INT4-G32 ROWS16 CPU experts) and Pascal SM61 (MXFP4 W4A8/DP4A CUDA experts). Test model
for the sprint: Qwen3.8-Flash-Next-FP8 (172.8 GB on the target box, AVX2 Ryzen 5 5600X +
GTX 1080 8 GB, Windows; final ask: a 4-bit auto-planned package of it).

## Existing seams (verified in tree, branch base)

- `pipeline.rs`: `CompileRequest{target,quant,codec,opt}` → `dry_run()/compile()`;
  global `ExpertQuantization{Exact,Mxfp4,Int4,Nvfp4}`; `record_inventory()` builds
  `LoweredRecord{id,kind,stored,decoded}`; **`ManifestRecord` already carries per-record
  `math_format/scale_format/layout`** — mixed formats are representable in the format
  today, they are just never varied (all records get 0/0/0 or 0xfffe).
- `target/mod.rs`: `TargetProfile` registry (portable-v1, apple8-v1, linux-x86_64-avx2-v1),
  `HostCapabilities{os,arch,avx2}` (std::env + is_x86_feature_detected only).
- `generated/target_registry.rs`: `TargetProfileSpec{allowed_layouts,...}` generated by
  `tools/gen_target_registry.py`.
- `quant/{int4,mxfp4,nvfp4}_record.rs`: `lower_expert()/stored_bytes()/resident_bytes()`.
- `storage`: `plan_records(records, profile, 4GiB)` → shards; manifest encode with records.
- C runtime: `coli_format_base.c` currently gates manifest open-check on
  profile allow-list; engine loads whole-record experts via `coli_executor_*`.

## Design — new module `colic/src/plan/`

### 1. MachineProfile (#192) — `plan/machine.rs`
```rust
pub struct MachineProfile {
  pub os: String, pub arch: String,
  pub cpu: CpuProfile,          // vendor, brand, cores_logical, avx2, avx_vnni,
                                // avx512{f,bw,vnni}, neon{i8mm,dotprod}
  pub ram_bytes: u64,
  pub gpus: Vec<GpuProfile>,    // backend: Cuda{cc_major,cc_minor,dp4a,tensor_cores,
                                //   native_fp8,native_fp4} | Metal{family} | None
  pub storage: StorageClass,    // Ssd | Nvme | Hdd | Network (+ --storage-class override)
}
```
- Probe: CPU flags via `std::arch::is_x86_feature_detected!`; RAM: `/proc/meminfo` (linux),
  `sysctl hw.memsize` (macos), `GlobalMemoryStatusEx` (windows, kernel32 via existing
  windows deps or raw FFI — check Cargo.toml before adding anything).
- GPU: CUDA via `nvidia-smi --query-gpu=name,memory.total,compute_cap --format=csv`
  (parse; DP4A = cc>=6.1, tensor = cc>=7.0, fp4 = cc>=12.0); Apple: profile implies Metal
  family-8 GPU. No new dependencies in v1.
- `colic probe [--json]` subcommand; `--machine-profile FILE` overrides probe with a
  synthetic profile (reproducible planning + tests without hardware).
- Capability vs policy split: MachineProfile records only facts (`dp4a: true,
  tensor_cores: false`); the cost model decides.

### 2. Physical IR (#193) — `plan/ir.rs`
```rust
pub enum MathFormat { Bf16, Fp8E4m3, Mxfp4, Int4G32, Nvfp4 }   // maps to existing ids
pub enum PhysicalLayout { Canonical, Apple8Tile, Rows16, PascalDp4aTile } // registry ids
pub enum BackendKind { Cpu, Metal, Cuda }
pub enum Placement { ResidentRam, ResidentVram, RamCache, VramCache, Pageable }
pub struct TensorPlan { semantic_key, role: Role, math, layout, backend, placement,
                        decoded_bytes, stored_bytes, lowering_id: &'static str }
pub struct PhysicalPlan { tensors: Vec<TensorPlan>, memory: MemoryBudgets,
                          decisions: Vec<Decision>, /* chosen + rejected + why */
                          machine: MachineProfile, objective, context, versions }
```
- Role classification reuses the semantic model's existing buckets
  (global/layer-static/resident/experts) + name patterns (`ffn.gate` → Router,
  `linear_attn` → Gdn, `ple_embedding` → NgramPle, `shared_expert`, `self_attn.indexer`
  → Qsa, `mtp` → Mtp).
- Unsupported (math,layout,backend) combos fail at planning time (maps to existing
  `reject_incompatible_target` paths). Apple8 becomes one lowering impl behind this
  boundary.

### 3. Memory planner (#194) — `plan/memory.rs`
- Inputs: geometry, `--context` (default min(model max_position, 8192)), kv dtype bf16,
  batch 1, layer_types hybrid split (full-attn vs GDN vs QSA indexer).
- KV: `2 * kv_heads * head_dim * ctx * 2B` per full-attn layer only. GDN: fixed state
  `vheads*kd*vd*4B` (mamba fp32). QSA: `idx_kv*idx_dim*max_pos*4B` per indexer layer.
- Output budgets: `{vram: total - reserve - kv - dense - scratch - expert_cache,
  ram: ...}`; fail early when KV alone exceeds budget; headroom policy 90%.

### 4. Cost model (#195) — `plan/cost.rs`
- `Objective{Quality, Balanced, Throughput, Latency, MinimumSize}` (new `--objective`
  flag; `--opt` stays as alias for size/latency).
- Deterministic rule tables v1 (`COST_MODEL_VERSION=1`):
  - x86_64+avx2 → routed experts INT4_G32 + Rows16 + Cpu.
  - cuda sm61 + dp4a → routed experts MXFP4 + PascalDp4aTile + Cuda.
  - metal apple8 → routed experts MXFP4 + Apple8Tile + Metal (existing behavior).
  - dense/router/norm/shared: Bf16 exact (v1; calibration may later downgrade).
  - PLE n-gram: FP8 if available else Bf16; residency preferred in RAM.
- Score = w_size*bytes + w_quality*risk + w_speed*est_matvec + w_io*io_cost with
  objective-dependent weights; every family records chosen + rejected + reason.

### 5. Placement (#199) — `plan/placement.rs`
Mandatory first (dense static resident), then PLE resident if it fits, then expert caches
from the remainder (VramCache for cuda reps, RamCache otherwise), Pageable storage always
the backing tier. Duplicate CPU+GPU rep only on explicit flag (v1 default off).

### 6. CLI + manifest (#201) — `plan/manifest.rs`, `main.rs`, `cli.rs`
- `colic probe`, `colic plan MODEL --target auto --context N --objective O [--json]
  [--machine-profile F]` → plan JSON to stdout / `-o plan.json`.
- `compile --plan FILE` replays a saved manifest: validates source fingerprint +
  planner/quantizer versions, refuses invalid overrides, then emits exactly the planned
  records. `--target auto` inside compile runs the planner inline.
- Determinism: BTreeMap ordering, no HashMap iteration in emitted output; full versions
  block in the manifest.

### 7. Mixed-representation ABI (#196)
- Emit per-record real `math_format/scale_format/layout` (fields already exist).
- New optional manifest field `rep_id` (u16): distinct per (semantic tensor, backend
  target); duplicates of the same rep_id = package error (verify.rs); distinct rep_ids
  for one semantic tensor are legal. Canonical/portable record = fallback rep.
- C runtime: record selection by runtime target (host probe at open), explicit fallback
  to canonical when the preferred rep is missing; unsupported combos fail cleanly
  (never reinterpret).
- Engine: `coli_executor_expert_info` gains layout awareness; qwen expert path dispatches
  rows16 vs canonical vs apple8 by the selected record's layout id.

### 8. Rows16 x86 target (#197)
- colic: int4-g32 rows16 packer (g32 fp32 scales, 16-row interleave) + new layout id in
  `gen_target_registry.py` (allowed on linux/windows x86_64 avx2 profiles).
- C: rows16 AVX2 matvec for the qwen expert path (reuse existing rows16 machinery where
  present), scalar reference parity test on the tiny fixture, canonical-vs-rows16 bench
  on the 5600X.

### 9. Pascal DP4A (#198)
- CUDA kernel: MXFP4 stays packed in VRAM; E2M1→int8 (×2 doubled values) in registers,
  per-group fp32→int8 activation quant, `__dp4a` accumulate int32, output scale =
  act_scale * (ue8m0_scale / 2). Gate/up/down matvec + fused gate_up variant.
- colic: PascalDp4aTile layout + lowering (tile order chosen from measured behavior).
- Bench on GTX 1080 vs existing MXFP4 fp32-decode CUDA path (the box already has the
  `qwen4k` CUDA test harness from the M-port session).

### 10. Calibration (#200) — `tools/calibrate.py`
- Deterministic numpy metrics per tensor family × candidate format: nRMSE, cosine error,
  per-block outlier stats; optional activation-weighted pass later.
- Emits `calibration.json` keyed by checkpoint fingerprint + quantizer version; planner
  consumes it as an optional input; objective floors veto formats below threshold.
- Not required for the rule-based milestone (explicit per #200).
